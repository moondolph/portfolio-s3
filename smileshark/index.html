~/why-this-role

왜 개발자에서 AWS 파트너 매니저인가

이미 해왔던 일

새 기능을 만드는 시간보다, 흩어진 정보를 맞추고 문서로 남기는 시간이 항상 더 길었습니다. 이 자리는 그 일에 정식으로 이름을 붙이는 결정입니다.

비교해서 고른 AWS

GCP·OCI를 실무로 다뤄봤기에, AWS가 가장 방대하고 정교한 생태계를 가지고 있다는 걸 비교하며 확인할 수 있었습니다.

언어라는 발판

영어(TOEIC 925)와 일본어(JLPT N1)로 훈련한 문서 독해력은, 대부분 영문인 AWS 자료를 다루는 데 그대로 이어집니다.

커리어 전환의 이유

AI가 개발 영역을 빠르게 잠식하는 흐름을 보며, 코드를 짜는 역할에만 머무르지 않고 기술과 파트너십을 함께 다루는 새로운 커리어로 전환하고 싶었습니다.

~/role-understanding

Understanding the Role

공개된 채용공고와 스마일샤크 공식 자료를 바탕으로 이해한 AWS Partner Manager의 업무 흐름입니다. 실제 내부 프로세스가 아니라, 지원을 준비하며 제가 구조화해 본 이해도임을 밝힙니다.

Opportunity → Validate → Design → Coordinate → Execute → Measure → Report & Improve — AWS 파트너 프로그램과 스마일샤크의 기술 역량을 고객의 영업기회로 연결하고, 그 성과를 데이터로 관리하는 흐름으로 이해했습니다.

AWS ACESalesforce / CRMSpreadsheetJira / Confluence / NotionSlack / Email

저는 이 직무를 단순 프로그램 운영이 아니라, AWS의 파트너 제도와 스마일샤크의 기술 역량을 고객의 비즈니스 기회로 연결하고 그 성과를 데이터로 증명하는 역할이라고 이해했습니다.
